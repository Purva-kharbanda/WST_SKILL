## Probable fix

### Pattern A ? Migration / data correction (primary)

- **Action:**    Identify and update all **Employee (`ENTITY_TYPE='T'`)** attribute rows whose **`CONTROL_TYPE` / `CONTROL_SUB_TYPE`** are **not valid v45 employee-attribute code-set values**; set to supported **`G`** pattern per **WFM-8487** and merged **PR #2233**.
- **Where:**     DB table **`RWS_ATTR`** ? columns **`CONTROL_TYPE`**, **`CONTROL_SUB_TYPE`**, optionally **`DEFAULT_ATTR_VALUE`** / **`DEFAULT_VALUE`** for date attributes.
- **Who:**       DBA (execute in maintenance window) + CSE (validate UI).
- **Risk:**      **Multi-customer** ? PR #2233 was TLB-scoped; unscoped UPDATE affects all tenants on shared QA DB ? **scope by `OWNER_ID` / `CLIENT_ID`** and dry-run first.
- **Verify:**    Re-open **IS_FLOATER** and **EMP_SENIORITY_DATE** on QA06 ? Attribute Type/Sub-Type populated; default acceptable to business.

```sql
-- INVENTORY ? run first on target tenant (replace $ownerId / $clientId)
SELECT ATTR_ID, NAME, ENTITY_TYPE,
       CONTROL_TYPE, CONTROL_SUB_TYPE, DEFAULT_VALUE,
       DISPLAY_TYPE, DATA_TYPE, DESCRIPTION
  FROM RWS_ATTR
 WHERE OWNER_ID = $ownerId
   AND CLIENT_ID = '$clientId'
   AND ENTITY_TYPE = 'T'
   AND NAME IN ('IS_FLOATER', 'EMP_SENIORITY_DATE');

-- Broaden: all employee attributes with unsupported control codes
SELECT NAME, CONTROL_TYPE, CONTROL_SUB_TYPE
  FROM RWS_ATTR
 WHERE OWNER_ID = $ownerId
   AND CLIENT_ID = '$clientId'
   AND ENTITY_TYPE = 'T'
   AND (CONTROL_TYPE NOT IN ('B', 'G') OR CONTROL_SUB_TYPE NOT IN ('B', 'G'));

-- WFM-8487 pattern (local: db2/20221011_2_41_DML.sql) ? VERIFY scope before apply
UPDATE RWS_ATTR
   SET CONTROL_TYPE = 'G',
       CONTROL_SUB_TYPE = 'G'
 WHERE OWNER_ID = $ownerId
   AND CLIENT_ID = '$clientId'
   AND ENTITY_TYPE = 'T'
   AND NAME = 'IS_FLOATER'
   AND CONTROL_TYPE = 'S'
   AND CONTROL_SUB_TYPE = 'M';
```
