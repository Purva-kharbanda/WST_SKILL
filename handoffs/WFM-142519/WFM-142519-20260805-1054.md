## Probable cause

- **Symptom:**     After clicking **Add** on listed Roster associate sub-tabs, a large empty white area appears at the bottom of the page below the add panel content.
- **Fault:**       `WebContent/scripts/roster/roster.payRule.renderers.js:showHideContactInfoPanel` (and parallel helpers in timeClocking, timeCollection, timeRounding, alternateWorkLocation renderers) â€” `showAddTemplateTab = show` was assigned **before** `updatePageHeight(show)`, so Angular rendered the bottom panel while `pageContentHeight` still reflected the full viewport.
- **Trigger:**     User opens Add (or Edit) bottom panel on any of the five roster entity tabs; outer `tab-content` and inner list `ng-style` height bindings use stale full `pageContentHeight`.
- **Consequence:** Total vertical space exceeds the viewport â€” user sees blank padding at page bottom; add panel may appear detached from list.
- **What raises to HIGH:** Git diff shows exact one-line reorder on all five files; template binds list height to `pageContentHeight` at two levels (`payRule.html:23,51`).

## Probable fix

> **[SKETCH]** Re-read each controller's `updatePageHeight` offsets (-52, -50, etc.) after applying; verify Close restores `pageContentHeightWOPopUp`.

- **File(s):**       Five roster renderers â€” reorder panel show/hide sequence
- **Change sketch:** Move `vm.showAddTemplateTab = show` out of the function entry. On show: call `updatePageHeight(false)` first, then `showAddTemplateTab = true`. On hide: call `updatePageHeight(true)` first, then `showAddTemplateTab = false`. This matches the working pattern needed so list height shrinks before the bottom panel mounts.
- **Blast radius:**  Same `showAddTemplateTab = show` anti-pattern exists in ~30 other roster renderers (grep hit); ticket scope is five tabs â€” broader audit optional follow-up.
- **Migration:**     none
- **PR scope:**      5 renderer JS files; manual UI smoke on all five tabs; optional BAT locator on Add/Close cycle
