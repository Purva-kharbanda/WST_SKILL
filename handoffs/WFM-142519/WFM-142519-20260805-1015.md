# Triage: WFM-142519 — Roster blank space at bottom when adding records on associate sub-tabs

## TL;DR

**Bug:** On Employee > Roster, clicking Add on Pay Rule, Time Clocking, Alternate Work Location, Time Rounding, or Time Collection opens the bottom add panel while the main list area still uses the full viewport height, leaving a large blank gap at the bottom of the page.
**Fix:** In each affected roster AngularJS controller, set `showAddTemplateTab = true` only **after** `updatePageHeight(false)` (and set `false` only after `updatePageHeight(true)` on close). Five renderer files already have this reorder in the local working tree.
**Action:** L3-Engineering — P3-next-sprint — commit the five renderer fixes, regression-test all five roster tabs on Add/Close, and consider applying the same pattern to other roster controllers that still assign `showAddTemplateTab` before `updatePageHeight`.

## Probable cause

- **Symptom:**     After clicking Add on roster associate sub-tabs, a large empty white area appears below the add bottom panel instead of the layout filling the viewport cleanly.
- **Fault:**       `WebContent/scripts/roster/roster.payRule.renderers.js:showHideContactInfoPanel` (and parallel functions in timeClocking, timeRounding, timeCollection, alternateWorkLocation renderers) — `showAddTemplateTab` is toggled before `updatePageHeight`, so Angular renders the bottom panel while `pageContentHeight` still equals the full viewport height.
- **Trigger:**     User clicks Add on any of the five listed roster sub-tabs; `ng-if="showAddTemplateTab"` includes the bottom panel HTML while outer containers still bind `ng-style="{height: pageContentHeight + 'px'}"` at the unadjusted full height (see e.g. `payRule.html` lines 23 and 51).
- **Consequence:** Main content area + bottom panel exceed the intended split layout → visible blank gap at page bottom; UX defect only (no data corruption).

## Probable fix

> **[SKETCH]** This code is triage-time analysis based on a static read of the fault site. Before applying, re-read the surrounding method and any downstream caller of the changed variable or return value. The fix stage (`/capture-fix`) will validate the diff against this sketch and flag any divergence in `Fix stage → Technical notes` with `[WARN: diff does not match Pattern B]`.

- **File(s):**       `roster.payRule.renderers.js`, `roster.timeClocking.renderers.js`, `roster.timeRounding.renderers.js`, `roster.timeCollection.renderers.js`, `roster.alternateWorkLocation.renderers.js` — reorder panel visibility vs height adjustment in each `showHide*Panel` function.
- **Change sketch:** Move `vm.showAddTemplateTab = true` to execute **after** `vm.updatePageHeight(false)` when opening; move `vm.showAddTemplateTab = false` to execute **after** `vm.updatePageHeight(true)` when closing. This matches the working pattern used in controllers where height is reduced before the bottom panel DOM is inserted.
- **Blast radius:**  Same anti-pattern exists in ~30 other roster renderer files (`showAddTemplateTab = show` before `updatePageHeight`); only the five tabs named in WFM-130904 were reported, but a broader sweep may be warranted.
- **Migration:**     No DB or config change.
- **PR scope:**      Five renderer JS files + BAT/UI manual on all five tabs; link PR to WFM-142519 / WFM-130904.

```javascript
// [SKETCH] — triage-time only; verify downstream callers before applying.
// Current (buggy) — HEAD version:
this.showHideContactInfoPanel = function (show) {
    vm.showAddTemplateTab = show;   // panel renders at full pageContentHeight
    if (!show) {
        vm.updatePageHeight(true);
        vm.selectedTab = "";
    } else {
        vm.updatePageHeight(false);
    }
};

// Suggested (already present in local working tree):
this.showHideContactInfoPanel = function (show) {
    if (!show) {
        vm.updatePageHeight(true);
        vm.showAddTemplateTab = false;
        vm.selectedTab = "";
    } else {
        vm.updatePageHeight(false);
        vm.showAddTemplateTab = true;
    }
};
```
