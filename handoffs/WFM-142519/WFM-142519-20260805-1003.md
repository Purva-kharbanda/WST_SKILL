# Triage: WFM-142519 — Roster blank space at bottom when clicking Add

## TL;DR

**Bug:** On Employee > Roster, clicking **Add** on Pay Rule, Time Clocking, Alternate Work Location, Time Rounding, or Time Collection shrinks the page but leaves a blank white band at the bottom instead of showing the add panel cleanly.

## Probable cause

- **Symptom:** After **Add** on the listed Roster sub-tabs, a blank white region appears at the bottom of the page; the add form panel does not occupy the reserved space correctly.
- **Fault:** `WebContent/scripts/roster/roster.{payRule,timeClocking,timeCollection,timeRounding,alternateWorkLocation}.renderers.js` — `showHideContactInfoPanel` / `showHideTimeRoundBottomPanel` / `showHideTimeCollectionPanel` sets `showAddTemplateTab` **before** `updatePageHeight()` (committed HEAD); plus `WebContent/ngtemplates/roster/{payRule,timeRounding,timeCollection,timeClocking}/` templates bind **both** outer tab container and inner list card to full shrunk `pageContentHeight` while bottom panel is an additional sibling (contrast `wages.html` list: `pageContentHeight - 56`).
- **Trigger:** User clicks Add → panel show path runs → height shrunk via `updatePageHeight(false)` but list div still claims entire shrunk height → bottom panel area renders empty or clipped.
- **Consequence:** Misleading UX on add flows across five Roster entities; functional save may still work if user scrolls, but appears broken (customer escalation WFM-130904 / COPPEL_SB).

## Probable fix

> **[SKETCH]** Triage-time static analysis. Re-read templates after JS change; verify in browser at 1366×768 and 1920×1080.

- **File(s):**
  - JS (partial fix already in local working tree, uncommitted): `roster.payRule.renderers.js`, `roster.timeClocking.renderers.js`, `roster.timeCollection.renderers.js`, `roster.timeRounding.renderers.js`, `roster.alternateWorkLocation.renderers.js`
  - HTML (still required): `payRule/payRule.html`, `timeRounding/timeRounding.html`, `timeCollection/timeCollection.html`, `timeClocking/timeClocking.html` — adjust list `ng-style` height to leave room for bottom panel (follow `wages.html` / `alternateWorkLocation.html` `-55` offset pattern)
- **Change sketch:** Move `vm.showAddTemplateTab = true|false` to **after** the matching `updatePageHeight()` call in each branch (working-tree diff already does this). Then fix template height bindings so the list section does not consume 100% of post-shrink `pageContentHeight` when the bottom panel is visible.
- **Blast radius:** All tenants using modern Roster Angular tabs (global UI pattern); not COPPEL-specific.
- **Migration:** None.
- **PR scope:** Five renderer JS files + four to five HTML templates; manual BAT on all five tabs Add/Close/Edit.

```javascript
// [SKETCH] — Current (HEAD — roster.payRule.renderers.js showHideContactInfoPanel):
this.showHideContactInfoPanel = function (show) {
    vm.showAddTemplateTab = show;  // BUG: binds panel before height recalc
    if (!show) {
        vm.updatePageHeight(true);
        vm.selectedTab = "";
    } else {
        vm.updatePageHeight(false);
    }
};

// Suggested (already present in local working tree):
this.showHideContactInfoPanel = function (show) {
    if (!show) {
        vm.updatePageHeight(true);
        vm.showAddTemplateTab = false;
        vm.selectedTab = "";
    } else {
        vm.updatePageHeight(false);
        vm.showAddTemplateTab = true;
    }
};
```
