### Root cause

The edit view used a mismatched layout structure for contract-hours labels and fields, so the `Daily Hours` row did not align consistently with the rest of the form when the record was opened for editing.

### Analysis

The issue appeared when users opened an existing Release Employee To Store record and the contract-hours section rendered in edit mode. That section used a different alignment pattern than neighboring rows, which caused visible label-field misalignment even though values were present and editable. This produced a UI quality defect on a core roster workflow.

### Fix

- Standardized the edit-form contract-hours row to the same flex alignment pattern used by the corresponding add flow.
- Updated `Minimum` and `Maximum` display labels in that row to use localization lookups, improving consistency for translated UI rendering.
- Added stable automation locators to the edited hourly input fields so regression checks can target this row reliably.

### Area impacted

- [DIRECT] Roster release-to-store edit form (all flavours): triggered when editing an existing record with contract-hours fields enabled.
- [REGRESSION] Roster release-to-store add/edit layout parity (all flavours): triggered when comparing contract-hours rendering between add and edit views.
- [DATA] Contract-hours configuration visibility (all flavours): required when DAILY_HRS and/or WEEKLY_HRS UI configuration flags are enabled.
