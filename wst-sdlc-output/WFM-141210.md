### Root cause

The Other Requests list was wired to show the opened request's submission time on every row instead of each peer request's own submission time, so managers could not see who requested off first.

### Analysis

When a store manager opened one associate's day-off request on Request Calendar and switched to the **Other Requests** tab, every row in the list showed the same **Requested On** date and time as the request they had open (for example, all rows showed 5/29/2026 7:59 PM while viewing Evan Lander's request), even though opening Tanganyika Turner's request individually showed 3/10/2026 4:33 PM. The defect appears whenever multiple associates have leave requests for the same period and the manager uses the Other Requests tab to compare submission order.

### Fix

- Each row in the **Other Requests** tab now displays that associate's own **Requested On** timestamp instead of repeating the currently selected request's timestamp.
- Screen-reader labels for Other Requests rows now announce the correct per-associate requested-on time for accessibility.
